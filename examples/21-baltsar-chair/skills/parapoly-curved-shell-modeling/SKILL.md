# 连续曲面厚壳建模

设计 BALTSAR 同类透明壳餐椅的比例、轮廓和部件关系时，先读 [透明壳餐椅设计](../parapoly-shell-chair-design/SKILL.md)；本 skill 负责曲面实体构造与技术验证，也可用于其他曲面厚壳。

先读取目标示例仓库规则、现有模型及验证记录。保持用户已确认的尺寸、款式和局部设计；用户指出一处问题不等于授权重做全部造型。路径按当前 workspace 解析，不沿用案例盘符。

本 skill 来自 BALTSAR 的实际迭代，侧重几何判断及验证。复用具体曲面、偏置公式或诊断工具时，读 [BALTSAR 案例与验证入口](references/baltsar-case.md)；不要把其中的毫米值、截面数量和验收阈值直接用于其他产品。

## 先把照片要求变成可检查的几何

- 分开记录整体包围盒、功能尺寸、正面轮廓、侧面曲线、自由边收口和部件内外关系。整体尺寸正确不代表形状正确。
- 遇到尺寸来源冲突，先沿用用户已作出的选择；缺少决定性信息时才澄清。保留“厂家尺寸”和“照片推定值”的区别。
- 宽顶圆肩等外观要求，用对应高度的真实网格截线宽度辅助约束；同时看正交正面、侧面和参考相近角度，不能只调一张透视预览。
- 画清透明壳、外侧承托、内侧软垫及支腿的装配关系。相邻曲面优先共享基准，减少分别拟合产生的穿插。

## 选择能保留实体和边界质量的构造

模型逻辑留在目标示例的单一 `main.code3d.js`，使用 `PartCode3dDocument` 并返回 `code3d_doc`。几何由当前 ParaPoly 函数生成；需要新能力时先检查本地 API 和 Native/Web 绑定，新增后实际验证两个后端，而不是借外部 STEP 掩盖能力缺口。

使用 `spline_loft` 时注意：

- 截面要平面、简单、闭合，点数相同、方向与接缝对应，不重复末端闭合点。本例构建的周期样条参数取自首截面的弦长分布；先检查当前实现是否仍如此。
- 首截面与其他截面的长宽比或点间距分布差异过大时，插值可能超调、自交或耗时异常。检查实际输出的尺寸、表面和有效性，不能只证明输入点合理。
- 分段曲线的一阶连续还取决于各段参数区间长度。接头切向量需换算到同一参数，而非只让控制点方向相同。
- 在纵向平面中做厚度偏置，会因横向曲面斜率而降低实际法线厚度。可做横向斜率补偿，但仍应在输出表面沿法线实测。
- 放样闭合不代表端面合理。检查两个终端是否形成大面积平面封口。需要圆滑自由边时，在几何中设计圆弧收拢或适用的内核圆角；独立边管及材质遮挡不能替代连续收边。
- 端部变小不能骤然夹断。平滑收拢、适当加密截面后仍要检查尖褶、超调和非流形网格。保留有限小封口时如实记录，不宣称没有任何平面或处处等厚。

只改变某个轮廓时，用平滑权重把修改限定在必要区域；已认可部件可比较截面定义或几何，明确哪些结果实际保持。

## 用互补检查排除“看起来没问题”

| 检查 | 能发现的问题 | 不能单独证明的事项 |
| --- | --- | --- |
| 包围盒、水平截线及正交视图 | 超调、比例错误、顶部收尖 | 壁厚、实体无穿插 |
| 输出网格的法线厚度探针 | 局部变薄、偏置补偿失效 | 全曲面的严格最小厚度 |
| CAD 交集体积 | 壳与内件相穿、支腿未接入 | 所有可见边缘都圆滑 |
| 网格边界/非流形/退化检查 | 端部坏网格、断裂及重叠边 | 外形符合参考图 |
| 同一模型的不透明局部图 | 透明排序掩盖的穿帮、平面截口、尖褶 | 可制造性、物理承载 |

CAD 交集先断言输入非空、面数为正。识别 RuntimeShape 包装与低层 Native ShapeHandle 的区别；本例通过独立文档 `build()` 取得句柄。不要把因参数类型错误得到的空结果当成“无相交”。用模型中确实应接触的组合或独立诊断输入做正向对照，防止整套检查空跑。

对用户报告的缺陷，先保留旧模型、源码和记录，用同一有意义的检查取得修复前失败及修复后通过的证据。门槛依据产品尺度和缺陷制定，不为让当前草案通过而放宽。网格修复也不能代替打开局部图检查实际收边。

## 双平台与交付

- 源码或建模条件变化后，执行受影响的 Native 和真实 Web/WASM 检查，覆盖导出及 STEP 回读。透明部件检查实际 GLB alpha；透明显示不是物理折射。
- Native/Web 可比较尺寸、部件、体积和材质；三角数可能不同，不要求字节或三角数相等。仅 Node 成功不能声称浏览器后端通过。
- 从同一已验证默认 GLB 更新预览及多视图。前后比较保持相机方向、画幅、显示覆写一致；存在对称部位时补充两侧局部，避免只修被截图的一侧。
- 使用项目已有多视图生成流程；检查图的隐藏、剖切、材质覆写仅作用于显示副本，记录输入哈希。验证结果绑定源码、验证器、构建、模型和图像，保持可追溯。
- 交付后按仓库约定更新该示例 `skills` 内的经验；只保留已验证且能改变后续判断的内容。技术检查和用户独立验收分开记录。
